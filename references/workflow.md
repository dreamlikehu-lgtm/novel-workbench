# 创作流程

## 先确定规模与作者参与方式

已有需求足够时提取并执行；否则合并询问真正缺少的信息：创意和人物困境、目标读者与语气、当前请求的篇幅、必须保留或避开的内容。用户可以让助手提出方案，不以问卷完成度作为开工条件。

短篇或单段改稿使用轻流程：明确意图→写作→针对性复查→交付。需要连续多章、跨会话续写或严谨状态时创建账本。字数默认口径为汉字；默认下限3000、无上限，但必须根据实际任务设置，不能把默认值强加给短章。

## 项目规划

使用脚本 init 后填写三份可读文档：

- `bible.md`：人物目标、处境、说话习惯、关系、世界规则、叙事视角。区分作者知道、读者知道、角色知道；不把未发生剧情写成当前状态。
- `outline.md`：全书方向、当前卷目标和近期章纲。章纲说明承接条件、人物尝试、阻碍、选择及后果。长篇按自然故事单元渐进展开，不一次填死全书，不预设固定50章窗口。
- `style.md`：语气、叙述距离、节奏、授权参考与原创基准段。用能读出差异的示例表达偏好，不依靠禁词表。首章完成后可选取合适段落补充基准。

先让作者评估人物、大纲和代表性段落，再大规模生成；用户已明确授权相应范围时直接推进。创作偏好保存在本书 style 中，跨书复用或保存私人偏好须遵循用户意愿。

## 逐章工作

1. **取上下文**：运行 context，取得当前 head、近三章原文、近20章摘要、当前事实与到期伏笔。按本章角色/线索提供 focus 可检索较早原文。检查被省略的事实键；关键词检索无命中不等于没有相关信息，必要时扩大范围并回读原章。超长项目可人工增补卷摘要，但它不能覆盖有原文证据的事实。
2. **明确本章用途**：结合近期章纲判断事件、人物关系或读者理解要发生什么变化。停顿、消化后果和日常相处可以有价值，不机械插入危机或反转。
3. **写正文**：按章节模板分区。写前最后回看上一章末段与文风范例。需要解决具体问题时读 craft 的相应模块，不一次加载全部指导。
4. **准备摘要和事实候选**：摘要保留关键事件及后果、人物已知/误解、真实打算、情绪关系、伤势、位置和物品归属。事实增量只写正文确立的变化，每条附准确原文依据。未来计划继续留在 outline。
5. **暂存并检查字数**：stage 接收正文、摘要和增量，返回版本标识与实际字数。字数不符时修正文后重新 stage。摘要或事实变化也重新 stage。
6. **两种审稿**：分别核对连续性与表达，审查同一组正文、摘要、事实增量和来源。表达审稿按 [小说语言复查](language-review.md) 检查句段和邻章中的表达习惯。可由宿主提供的不同审稿代理或作者执行；没有独立执行条件时由主代理分两轮检查并披露。记录真实执行者和检查依据，不生成虚构的审稿结论。
7. **修复与提交**：blocking 问题先改，重跑受影响审稿。最多3轮作为默认工作预算；仍无法解决时保留草稿和失败原因并报告，不标为完成。commit 只接受当前来源和当前候选的两种通过记录。
8. **继续约定范围**：提交后取得新 head，进入下一章。用户只要求局部修改时完成该局部，不触发后续批量写作。

## 审稿重点

连续性检查：因果成立，时间/年龄/人数/资源数值自洽，角色行为受其信息与动机约束，场景衔接自然，伏笔回收不偷换含义；摘要和每条事实值确实由引用原文支持，未把计划、误解或谎言提升为客观事实。

表达检查：人物有可区分的声音，动作与环境细节服务当下选择，去掉重复解释，节奏适合本章用途；章末可以留下问题、行动或情绪余韵，不强制悬念。

将语言复查纳入同一份 `scope=craft` 报告，记录具体问题、处理与保留依据。新章写作或改稿已有授权时，在约定范围内完成修复和复查。仅检查的任务交付诊断；涉及新的剧情方向时按用户意图处理。局部润色后核对事实、摘要和证据，重新 stage，并重新完成连续性与表达审稿。历史章节沿用下方的分支修订流程。

## 中断续写

先 status，再 context；检查待处理草稿、来源变化和导出视图差异。账本已有提交但 Markdown 缺失时，用 export 重建视图，不重写或重复提交该章。草稿有失败审稿时从问题处继续，不把文件存在视为通过。

## 历史修订

已验收章节不直接覆盖。先将手工改稿另存，再 `fork --from-chapter N --to 新目录`，新分支只保留第N章之前的已验收事实；将改稿作为第N章新候选重新执行流程。后文必须逐章核对重提，不沿用旧状态或旧审稿。

fork 保留原项目；设定文档取分支创建时版本，助手须检查是否包含后来才应揭示的内容。这个首版没有自动推断全部历史影响的功能，不能声称完成全书一致性修复。

## 可视化与导出

`dashboard` 生成离线 HTML 快照，显示章节、待处理项、事实来源与到期伏笔，可搜索与展开正文。它是只读面板，不能在其中改稿，更新后需重新生成。

`export` 汇总已验收章节为 Markdown。首版不直接提供 EPUB、向量检索或联网发布；有此需求时明确新增任务和对应工具，不伪称内置。
